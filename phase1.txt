4  Authentication and security

4.1 Registration & Login [3 Marks]
4.1.1 Participant Registration
• IIIT Participants: Must register using IIIT-issued email ID only (email domain validation
mandatory) (Assuming no passwords needed), implement password as well
• Non-IIIT Participants: Must register using email and password

4.1.2 Organizer Authentication
• No self-registration. Organizer accounts are provisioned by the Admin.
• Organizers login using credentials (passwords) provided by the Admin.
• Password resets must be requested and handled by the Admin 


4.1.3 Admin Account Provisioning
• Admin is the first user in the system. (assume there is going to be only 1 admin who will never change)
• Admin email and password are provisioned and handled by the backend only (no UI regis
tration).
• Admin has exclusive privileges to create/remove clubs/organizers.
4.2 Security Requirements 
• Passwords must be hashed using bcrypt (no plaintext storage)
• JWT-based authentication is mandatory for all protected routes
• All frontend pages (except login/signup) must be protected with role-based access control
4.3 Session Management 
• Login must redirect the user to their respective Dashboard; sessions must persist across
browser restarts unless explicitly logged out; logout must clear all authentication tokens.
